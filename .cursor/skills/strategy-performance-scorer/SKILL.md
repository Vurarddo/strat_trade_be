# Strategy Performance Scorer

Description: Аналітичний інструмент для підрахунку метрик бінарних опціонів.

Input: DataFrame з історією угод (ціна входу, ціна закриття, час експірації, напрямок, виплата брокера).

Process: Аналізує масив угод. Обчислює Win Rate, Profit Factor, Maximum Drawdown, кількість угод підряд у плюсі/мінусі (Streak), та очікувану математичну вигоду (Expectancy).

Output: Генерує текстовий звіт (Markdown) зі статистикою та графік балансу (equity curve), щоб розробник міг швидко оцінити стратегію.

## Інструкції для агента

1. **Чисті функції**: логіку метрик тримати в **`domain/`** або окремому аналітичному модулі без I/O; вхід — уже нормалізований **DataFrame** (узгоджені імена колонок; час — timezone-aware).
2. **Визначення метрик** (узгодити з колонками вхідних даних):
   - **Win rate**: частка прибуткових угод за правилом ITM/виплати брокера.
   - **Profit factor**: сума виграшів / |сума програшів| (узгодити обробку нуля).
   - **Max drawdown**: максимальне падіння кумулятивного PnL / equity від локального максимуму.
   - **Streaks**: максимальні серії виграшів і програшів підряд.
   - **Expectancy**: середній очікуваний результат на угоду (R у термінах PnL на ставку, якщо задано stake).
3. **Звіт Markdown**: таблиця ключових метрик, короткі пояснення припущень, попередження при малій вибірці.
4. **Equity curve**: побудувати кумулятивний баланс по часу (наприклад `matplotlib` → PNG у `artifacts/` або тимчасовий шлях) і **посилання або вставка** у звіт; не зберігати секрети в шляхах.
5. **Шари**: не змішувати підрахунок з **адаптерами** брокера; результати бектесту подаються як DataFrame/CSV, що вже зійшов з двигуна.

Для узгодженості з архітектурою див. **`trading-backend-architecture-backtesting.mdc`** та **`quantitative-strategy-backtest-engineer`** (субагент) — семантика бінарного опціону (експірація, виплата) має бути явно задокументована в звіті.
